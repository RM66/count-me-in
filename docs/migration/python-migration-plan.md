# Go → Python API Migration Plan (autonomous-agent runbook)

Scope: replace the Go API in `apps/web/api` + `apps/web/pkg` (module `countmein`, single Vercel Function `api/entry/index.go`) with a Python/FastAPI API with **byte-compatible HTTP behavior**. Next.js (`apps/web/src`), Auth.js (`src/app/api/auth/[...nextauth]`), `packages/*` (Drizzle schema + migrations stay the schema owner), and the Zod contract manifests (`packages/contracts/src/wire.ts`, `routes.ts`) are **not** migrated and must not change behavior.

## 0. Global rules (apply to every step)

1. **Source of truth for the wire:** `apps/web/openapi.yaml`, generated from Zod by `bun run generate:openapi`. Python never hand-edits it. Python models are generated _from_ it.
2. **Source of truth for behavior:** the Go code and its tests _at the commit where Phase 1 starts_ (record it as `GO_BASELINE_SHA` in `docs/migration/baseline.txt`). When Go code and docs disagree, Go code wins; log the discrepancy in `docs/migration/discrepancies.md`. **Resolution rule:** a discrepancy is _ported as-is_ to Python (byte-compatible behavior is the goal), recorded in `discrepancies.md`, and only fixed — deliberately, in both sides or in the spec — after the Phase 6 cutover. Never "improve" behavior mid-migration.
3. **Never edit `*_gen.py`** (same rule as `*_gen.go`). Hand-written code lives in non-`_gen` files.
4. Do not stage or commit unless the orchestrating user/pipeline instructs it. Each phase ends with a "gate" — all its verification commands must exit 0 before the next phase starts. If a gate fails 3 times in a row on the same cause, stop and write the failure to `docs/migration/blockers.md`.
5. Working directory for all commands is `apps/web/` unless stated otherwise.
6. Go stays buildable and deployed until Phase 6 cutover gate passes locally; Go source is deleted in Phase 5 only after the parity gate (5.0) is green.
7. Preserve every invariant in `AGENTS.md` → "Conventions" (atomic seat reserve, demo organizer write refusal, consumed guest ticket, QStash after commit, outbox idempotency, manage-token hashing/expiry, delete 409 guards, media cleanup, healthz, rate limiting, `TRUST_PROXY_HEADERS`, `STRICT_ENV`, i18n of API errors). Each one gets an explicitly named test (see 4.3).

## Fixed technology choices

| Concern                                  | Choice (pinned major)                                                                                                   | Why it fits Vercel serverless                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Python                                   | **3.12** (`.python-version` = `3.12`)                                                                                   | Supported by Vercel Python runtime; stable wheels for all deps below.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Dependency mgmt                          | **uv** (`pyproject.toml` + `uv.lock`), exported to `apps/web/requirements.txt` for Vercel                               | Deterministic lock; Vercel's runtime reliably installs `requirements.txt`. CI fails if export is stale.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Web framework                            | **FastAPI 0.115+**, ASGI app exported as `app`                                                                          | Vercel Python runtime serves ASGI apps natively; one app = one "fat" function (mirrors current Go design, one cold start shared by all routes).                                                                                                                                                                                                                                                                                                                                                                             |
| Schemas                                  | **Pydantic v2** models generated by **datamodel-code-generator** from `openapi.yaml`                                    | Rust core → fast validation; codegen keeps spec↔code drift a CI failure (replaces oapi-codegen).                                                                                                                                                                                                                                                                                                                                                                                                                            |
| DB access                                | **SQLAlchemy 2.0 Core (async)** + **psycopg 3** (`psycopg[binary]`), `NullPool`, `prepare_threshold=None`               | No ORM identity-map overhead; Core expresses the conditional `UPDATE … WHERE booked_count + :seats <= capacity` exactly; `NullPool` + no server-side prepared statements is safe behind a transaction-mode pooler (PgBouncer/Neon/Supabase) and does not leak connections across frozen serverless instances. asyncpg rejected: needs statement-cache workarounds behind PgBouncer. Prisma Client Python rejected: extra Node/Rust engine binary bloats bundle and cold start, and would duplicate Drizzle as schema owner. |
| Redis                                    | **redis-py 5 (`redis.asyncio`)**                                                                                        | Same wire semantics as go-redis (`SET NX EX`, `GETDEL`). Client created per invocation-scope lazily, no pool warm-up.                                                                                                                                                                                                                                                                                                                                                                                                       |
| Outbound HTTP (Telegram, QStash publish) | **httpx** (async)                                                                                                       | Also the test client.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| QStash signature verify                  | **qstash** (official Upstash Python SDK) `Receiver`                                                                     | Official JWT verification, equals Go `pkg/jobs/receiver.go`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| R2 (S3) presign + delete                 | **boto3** (lazy-imported inside `storage` functions only)                                                               | Proven SigV4; lazy import keeps it off the cold path for non-media routes.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Logging                                  | stdlib `logging` + custom JSON formatter (`countmein/logx.py`)                                                          | One JSON object per line on stdout = what Vercel log drains parse; field names copied from `pkg/logx/logx.go`. No extra dependency.                                                                                                                                                                                                                                                                                                                                                                                         |
| Tests                                    | **pytest 8**, **pytest-asyncio**, **httpx** `ASGITransport`, **fakeredis**, **respx**, real Postgres 17 + Redis 7 in CI | Direct analogues of Go tests (`miniredis` → fakeredis, `httptest` → ASGITransport).                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Lint / types                             | **ruff** (lint + format), **mypy --strict**                                                                             | Required by brief.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Contract diff                            | **oasdiff** (CLI, pinned version via `go`-free binary release)                                                          | Detects breaking changes between the Zod spec and FastAPI's emitted spec.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Local server                             | **uvicorn** on port **3001** (same as `cmd/dev`, `PORT` env override)                                                   | Next dev proxies to the same port; no Next config change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## Phase 1 — Discovery & contract mapping

### 1.1 Record baseline

- **Prereq:** clean working tree. **Working directory for this step is the repo root** — `docs/migration` lives at the root, and rule 5's `apps/web` default would create `apps/web/docs/` instead.
- **Actions (repo root):** `mkdir -p docs/migration`; write `git rev-parse HEAD` to `docs/migration/baseline.txt`.
- **Output:** `docs/migration/baseline.txt`.
- **Verify (repo root):** `test -s docs/migration/baseline.txt`.

### 1.2 Endpoint inventory

- **Actions:** Parse `packages/contracts/src/routes.ts` and `apps/web/openapi.yaml`; produce a table of every operation: method, path, auth kind, request schema id, response schema id(s) per status, Go handler (`pkg/routes/*.go` func), guards applied (`pkg/httpx/guards.go`), rate-limit bucket, demo guard, side effects (DB tables written, QStash queue, R2). Include the out-of-spec route `/api/healthz`, marked with an explicit `in_spec=false` column so spec rows and infrastructure rows are counted separately (no "row count minus one" arithmetic). **Do not hardcode an expected operation count** — the script derives it from `openapi.yaml` (at baseline it is 23: auth ×2, organizers ×6, services ×5, slots ×5, bookings ×4, jobs ×1 with queues from `packages/contracts/src/jobs.ts`).
- **Output:** `docs/migration/endpoints.md`.
- **Verify:** `scripts/migration/check-inventory.ts` (run with `bun` from `apps/web`) parses `openapi.yaml` itself and asserts every spec operation appears in `endpoints.md` exactly once, plus the healthz row.

### 1.3 Types, schema, middleware, env inventory

- **Actions:**
  - Map every Go struct in `pkg/contracts`, `pkg/db`, `pkg/jobs`, `pkg/auth` → target Python module/class (`docs/migration/types.md`).
  - Map every DB table/column/index/constraint used by `pkg/db/*.go` against `packages/db` Drizzle schema (`docs/migration/db.md`), incl. every raw SQL string (copy verbatim; they will be reused as `sqlalchemy.text()` or Core expressions).
  - Map middleware chain in `pkg/api/server.go` + `pkg/httpx/middleware.go` in order (`docs/migration/middleware.md`): panic recovery, request id, logging, `_path` rewrite restoration, client IP, rate limit, spec validation, error → JSON mapping. Include the externally visible limits: request body bound at 1MB (`httpx.ReadBodyOr413` → 413), healthz probe timeout 2s, post-commit publish budget 1500ms, media cleanup timeout 3s, outbox mark timeout 5s.
  - Enumerate env vars: `grep -rhoE 'os\.(Getenv|LookupEnv)\("[A-Z_0-9]+"' pkg api cmd | sort -u` **plus** the loop-read names — `config.go`, `api/server.go` and `storage/r2.go` read some variables via `os.Getenv(name)` from slices, which the call-site grep misses; scan those files for `"[A-Z][A-Z0-9_]{2,}"` literals as well. Record required/optional/production-required (`config.Validate`) in `docs/migration/env.md`.
  - Map every Go test file → planned pytest file (`docs/migration/tests.md`), one row per `func Test…`. Note: `t.Run` subtests and table cases are not separate rows — the porting unit is the top-level `func Test`; subtest coverage is preserved by porting the table bodies. To make a lost table case visible, each row carries `cases: N` — the number of `t.Run` subtests / table entries in the Go test (0 for plain tests); the ported pytest must keep at least that many cases.
  - Document Go's JSON wire encoding (`docs/migration/json-encoding.md`): `encoding/json` HTML-escapes `< > &` (`\u003c` …) unless disabled; `time.Time` renders RFC3339Nano; `omitempty` fields vanish, non-`omitempty` pointers render `null`; key order follows struct field order; `json.Encoder` appends a trailing `\n` (note which handlers use `Encode` vs `Marshal` — `httpx.Response.Write` uses `Marshal`, no trailing newline, and sets `Content-Length`). Source: `pkg/httpx/response.go` + golden transcripts.
- **Verify:** `scripts/migration/check-inventory.ts` additionally asserts: every runnable Go test from `go test -list '.*' ./pkg/... ./api/...` (the source of truth — the raw grep overcounts by `TestMain` and build-tagged helpers) appears in `tests.md`, matched on word boundaries (`TestFoo` must not satisfy `TestFooBar`); every env var from both greps appears in `env.md`.

### 1.4 Freeze behavioral fixtures from Go (golden HTTP transcripts)

- **Prereq:** local Postgres + Redis: `docker compose up -d` at the repo root (services `postgres:17`, `redis:7`), then `set -a; source .env; set +a` and `bun run db:migrate` in `packages/db`.
- **Actions:**
  - Write `apps/web/tests_py/parity/scenarios/*.yaml`: ordered request lists covering every endpoint × {happy path, each validation error class, auth missing, demo organizer refusal, 404, 409 delete guard, capacity exhausted, expired manage token, replayed guest ticket, merge-patch absent/null/pair rule, rate limit 429, QStash bad signature, duplicate `outboxId`}. **Time-dependence:** scenarios create their own data with dates relative to `now` and a wide margin (±30 days) — the demo seed is _not_ used as scenario data (it re-lays slots every day from today); "expired token" is forced by a DB update, "past slot" by an explicit old date. Credential minting is a single fixed decision: tickets are written **directly into Redis** with the exact key format of `auth/ticket.go` (`auth:ticket:{token}`, same JSON payload); the organizer session is a JWT minted with the `pkg/authtest` algorithm (HS256, HKDF-derived key) — no Auth.js cookie encoding is needed because the Go API reads the `X-Organizer-Auth` header, not a cookie.
  - Write `scripts/migration/record.py`: starts `go run ./cmd/dev` on port 3101, resets DB (**TRUNCATE of every table in the public schema** except Drizzle's migrations table — a hardcoded list would let a new table stay dirty) **and Redis (`FLUSHDB`) — including rate-limit buckets, tickets and outbox claim keys — before each scenario**, sends requests, stores `{status, headers, body, body_raw}` to `tests_py/parity/golden/<scenario>.json`. **All response headers are recorded except an exclusion list** (`date`, `x-vercel-*`, `content-length`) — the middleware sets security headers the parity check must see. `content-length` is recorded as the **fact** `contentLengthMatchesBody` (header == `len(body_raw)`) plus `transferEncodingChunked: false`, not as a number — Go's RFC3339Nano drops trailing zeros, so timestamp lengths (and thus the header) float run to run; the byte-level pin lives in `body_raw`, which keeps the raw response bytes with the same substitutions, so the byte-level JSON rules of `json-encoding.md` (HTML escaping, key order, trailing newline, spacing) are verifiable in replay. UUIDs, timestamps, tokens, presigned URLs are normalized to placeholders (`<uuid:1>`, `<ts:1>`, stable by first appearance). Timestamp **relations are NOT recorded**: the only timestamp pair any response carries is server-generated `createdAt` next to scenario-authored `startsAt` — a delta that floats run to run and cannot be asserted; and the manage-token **+24h expiry is not on the wire** either (the guest DTO carries only `canCancel`). Timestamp invariants are asserted in the db/contracts tests (`TestCanCancelBooking`), not in HTTP goldens. A step may declare `expectSink: N` — the recorder then waits up to 2s (the publish budget is 1500ms) for exactly N outbound calls and **fails the recording** if fewer arrive, so a late publish can never silently record `sink: []`. **Every step that creates or cancels a booking (POST `/api/bookings`, `/api/bookings/cancel`, `/api/bookings/cancel-by-organizer`) MUST declare `expectSink`** (0 on refusal paths — no publish is itself an assertion); `check-inventory.ts` enforces this. A 429's `Retry-After` is recorded as the class `<retry-after:seconds>` plus the separate checkable fact `retryAfterWithinWindow` (0 < v ≤ the path's rate-limit window).
  - **Outbound stubbing — what is possible via env:** QStash publish is redirected with `QSTASH_URL` to a local recorder (`scripts/migration/sink.py`); R2 presigning is made deterministic with fake credentials (the SigV4 signature is normalized away). **Telegram cannot be redirected** — `telegramAPIBase` is a code constant (`pkg/jobs/telegram.go`), not an env var — so job-handler _send_ behavior is **not** captured in HTTP goldens; it is ported from the Go tests (`pkg/jobs/*_test.go`, incl. `fakeTelegram`) exactly as the rest of the Go test suite. The recorder uses a fake `TELEGRAM_BOT_TOKEN` so widget HMAC is deterministic; job scenarios that would send Telegram messages are covered by the Go tests, not by transcripts.
  - The recorder is Python (run with `uv run --project scripts/migration`) with its **own** `scripts/migration/pyproject.toml` — this is tooling, not the Phase 2 API scaffold, so it does not violate the phase ordering; the API's `pyproject.toml` still arrives in 2.2.
- **Output:** golden transcripts, one per scenario.
- **Verify:** record twice and compare the two golden dirs with `diff -r` (the first copy goes to a fresh `mktemp -d` dir, so reruns never nest directories and parallel runs never collide): `RUN1=$(mktemp -d) && uv run --project scripts/migration scripts/migration/record.py && cp -R tests_py/parity/golden/. "$RUN1"/ && uv run --project scripts/migration scripts/migration/record.py && diff -r "$RUN1" tests_py/parity/golden`. Additionally `check-inventory.ts` verifies golden coverage step by step: the matrix in `endpoints.md` is `operationId × error class → scenario#step → expected status`, and the script asserts the golden transcript at that step really answers that status (file existence alone proves nothing), that every booking create/cancel step declares `expectSink`, and the per-step facts `contentLengthMatchesBody` / `transferEncodingChunked` / `retryAfterWithinWindow`.

### 1.5 Automated contract validation design

- Contract check (implemented in 2.4, enforced in CI): FastAPI emits `app.openapi()`; `scripts/export-py-openapi.py` writes `openapi.py.yaml`; `oasdiff breaking openapi.yaml openapi.py.yaml --fail-on ERR` must pass **and** `oasdiff breaking openapi.py.yaml openapi.yaml --fail-on ERR` must pass (bidirectional = equivalence at breaking level). Additionally a pytest asserts the set of `(method, path)` pairs is identical.
- Shared vectors reused unchanged: `packages/contracts/vectors/{validation,domain}` and `pkg/contracts/testdata/golden` (moved to `tests_py/contracts/golden` in Phase 5).

**Phase 1 gate:** `bun scripts/migration/check-inventory.ts` exits 0; 1.4 determinism check exits 0.

### 2.3 Vercel configuration (Hobby tier)

- Edit `apps/web/vercel.json` **in Phase 6 only** (switch-over). In Phase 2, create the target content in `docs/migration/vercel.target.json`:

## Phase 3 — Core implementation

Order is dependency order. For each module: (a) port Go file(s) listed, (b) port its Go tests per `docs/migration/tests.md` into `tests_py/<module>/test_*.py`, keeping test names (`TestFooBar` → `test_foo_bar`), (c) run the verification. Go comments explaining _why_ are ported; do not reference Go files in Python comments.

## Phase 6 — Verification & cutover

### 6.1 Switch Vercel config

- Performed atomically with 5.1 (see the ordering rule there): `vercel.json` already points at `api/index.py`, the entry exists, and `api/_lib/index.py` is gone. Remaining here is only the local build check.
- Local build: `bunx vercel build` (requires `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` in env; `bunx vercel pull --yes --environment=preview` first). Assert via `uv run python scripts/migration/check_bundle.py`: `.vercel/output/functions/api/index.func` exists, contains `_lib/countmein/app.py`, and is < 200 MB.

### 6.2 Preview deploy + smoke

- `bunx vercel deploy --yes > .vercel/preview-url.txt` (preview env vars must already exist in the project — required list from `docs/migration/env.md`; check with `bunx vercel env ls preview` and fail listing any missing).
- `scripts/migration/smoke.py <url>` (uses `VERCEL_AUTOMATION_BYPASS_SECRET` as `x-vercel-protection-bypass` header if deployment protection is on): `GET /api/healthz` → 200; `GET /api/organizers/me` unauthenticated → 200 demo-organizer profile (golden `organizers-me` step 0 — sessionOrDemoRead, never 401); public read of `/demo` page 200; demo-organizer write → refused body identical to golden; validation-error POST → golden body; POST `/api/jobs/booking.created` without signature → golden status (401) with empty body; measure the first request (cold start when run right after deploy — the perf record carries a cold/unknown marker) and p50 of 20 warm `healthz` calls — record in `docs/migration/perf.md`; fail if any request exceeds 10 s or a marked-cold first request > 3 s.
- Parity against preview: replay the read-only and demo-refusal subset of parity scenarios (no destructive writes to shared DB, no rate-limit bucket exhaustion) with `uv run python scripts/migration/replay_remote.py <url>` (also honors `VERCEL_AUTOMATION_BYPASS_SECRET`); must match golden, including the security headers the goldens pin.

### 6.3 Production cutover

- Merge PR only after: CI green, 6.2 green. Production deploy is Vercel's git integration on merge. Immediately run `scripts/migration/smoke.py https://countmein.group`.
- Rollback criterion: any smoke failure, or the share of 5xx responses above 1% within 30 min (`bunx vercel logs https://countmein.group --json --since 30m` piped through `scripts/migration/errors_rate.py`, which dedupes the app's own log lines against Vercel's access lines by request id). Exit 1 = rollback (`bunx vercel rollback` to the previous production deployment, then `git revert` the merge commit on a new branch); exit 3 = inconclusive (fewer than 50 requests in the window — NOT a rollback signal: widen the window, e.g. `--since 2h`, or rely on the smoke check as the criterion).
- Run QStash schedules check (`CHECK=1 bun run qstash:schedules`) — read-only: destination URLs are unchanged (`/api/jobs/{queue}`), so it must report no drift and exit 0; any drift is a failure. (Without `CHECK=1` the script reconciles — creates/deletes — which must never happen as part of cutover verification.)

### 6.4 Close-out

- Delete `docs/migration/` scratch artifacts except `perf.md` (summary folded into ADR-021 "Consequences") and this plan (the runbook stays as the record of how the migration was executed); delete `scripts/migration/` **but keep** `tests_py/parity/scenarios` — they are `test_replay.py`'s input data, not recorder tooling — and keep `tests_py/parity/golden` + `test_replay.py` as permanent regression tests.
- **Ordering:** the production smoke (6.3) and the 30-min 5xx watch must both be green **before** this close-out deletes anything; the final gate re-runs the suites that remain afterwards.
- **Final gate:** `bun run test`, `bun run lint:py`, 5.1 zero-Go checks — all exit 0 (the production smoke already passed in 6.3, before the tooling was deleted).
