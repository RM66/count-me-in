# ADR-026: Telegram OIDC login replaces the legacy widget

- **Status:** Accepted
- **Date:** 2026-10
- **Amends:** [ADR-008](008-messenger-only-auth.md) (proof layer only)

## Context

The legacy Login Widget (`telegram-widget.js` iframe + `data-onauth` eval + server-side HMAC over a data-check-string) is superseded by Telegram's OIDC login at `oauth.telegram.org`. The widget forced `'unsafe-eval'` into production `script-src`, had no replay protection inside its 24h window, and is the archived API. Everything below the "proof of Telegram identity → ticket" abstraction — auth tickets, `purpose` binding, the Credentials provider, login links, `X-Organizer-Auth`, `consume_guest_ticket` — is unchanged. Every load-bearing assumption below was verified against the live `oauth.telegram.org` server before adoption.

## Decision

- **Client:** `TelegramLoginButton` + `useTelegramLogin` orchestrating `useNoncePairs`, `useTelegramPopup`, `useInAppHandshake`, `useTelegramTicketExchange` on top of `telegram-oidc.ts` + `telegram-inapp.ts` (no `.tg-auth-button`, no `data-*` auto-init). The page generates `nonceVerifier` (32 random bytes, base64url) and passes `nonce = b64url(sha256(nonceVerifier))` to Telegram — a PKCE-style proof-of-possession with no server roundtrip and no nonce endpoint. Every pair handed to Telegram lives in a component-local `Map<nonce, verifier>`; a result is paired **by the nonce inside its token** (never by click order — in-app, a repeat tap replaces the lib's callback), consumed once, dropped after unmount.
- **Two delivery paths, one result shape.** Inside the Telegram WebView (`window.TelegramWebviewProxy`) the `telegram-login.js` lib drives `/inapp` — the only upstream branch that sends `origin`. Everywhere else we build `/auth?response_type=post_message&…&origin=…` and listen for `auth_result` ourselves: the stock lib's popup path omits `origin` and is upstream-broken. The in-app readiness gate waits for `oauth_supported` with a 500 ms grace, after which the click falls back to the manual popup (proven inside the Android WebView).
- **API:** `POST /api/auth/telegram-{guest,signup}` take `{idToken, nonceVerifier}`. `validate_telegram_id_token` verifies RS256 against `https://oauth.telegram.org/.well-known/jwks.json` (1h in-process cache, at most one network attempt per 60s while a set is cached — refresh, outage retry and unknown-`kid` refetch share the budget — concurrent callers share one in-flight fetch on the same loop, and an empty-cache failure fast-fails for 10s rather than paying the fetch timeout per login — fail-closed with no usable key, stale cache survives outages), checks `iss`/`aud`/`exp`/`iat` (freshness window −60s…+600s), requires `sha256(nonceVerifier) == claims.nonce`, and claims the nonce single-use in Redis (`auth:oidc-nonce:{nonce}`, `SET NX`, TTL = `exp` + leeway remaining — the whole acceptance window, **fail-closed** per ADR-019 — cryptographic checks run first so junk never touches Redis). Every token-level failure answers identically `telegramValidationFailed`; the real cause is a rate-limited `reason` log field — tokens and verifiers are never logged.
- **Identity:** `aud` == Client ID == the numeric bot id, derived from `TELEGRAM_BOT_TOKEN` (no new server env). `claims.id` — a digit string, never `sub` — maps to `messenger_id` unchanged: **no DB migration, no session invalidation**. `picture` (`t.me`/`*.telesco.pe`, https-only) becomes `photo_url`. Scope `['profile','write']` keeps the bot DM grant (`telegram:bot_access`) — no phone scope.
- **Config:** `NEXT_PUBLIC_TELEGRAM_CLIENT_ID` replaces `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`; `next.config.js` fails the build when both it and `TELEGRAM_BOT_TOKEN` are set and disagree. CSP: `'unsafe-eval'` dev-only, `connect-src` gains `oauth.telegram.org` (in-app `/inapp`), `frame-src 'none'` outside previews.

## Trust boundary

The verifier binding makes a leaked token useless and binds it to the page that started the flow. It does **not** stop a flow an attacker starts himself with his own verifier — that rests on Telegram delivering tokens only to registered origins (popup `postMessage` target, in-app `origin` check). Verified against the live server: an unregistered origin receives no `auth_result`, and `/inapp` is refused (`Bot domain invalid`); every login shows the consent sheet again. Recorded as an explicit trust assumption.

## Consequences

- Cutover is a single switch (no dual-run): deploy the code, then flip the bot to OIDC in BotFather and re-register Allowed URLs — the switch both wipes the list and stops the legacy widget, so a minutes-long login gap is inherent. Rollback = Vercel Instant Rollback while Telegram still serves the archived widget; browser cache is not rolled back.
- Fallbacks, if Telegram ever rejects the client-generated nonce: a server-issued nonce endpoint (popup, no secret); the manual `code` flow (needs `TELEGRAM_CLIENT_SECRET`) is the last resort.
- iOS in-app verified on a real device (2026-10-25): `TelegramWebviewProxy` present, the lib loads under CSP, `oauth_supported` arrives through the wrapped `receiveEvent` — the lib installs it on both `Telegram.WebView` and `Telegram.TelegramGameProxy`, and which object the WebView invokes is not observable from the page, so both stay wrapped — and the native consent sheet completes the `/inapp` flow end to end (signup minted `messenger_id = <numeric id>` from the `id` claim; the next login landed straight in `/cabinet`). Android has no proxy — the manual `window.open` path serves it inside the webview. Previews can't log in — unchanged from the legacy `/setdomain` limitation.
- Upstream defect worked around client-side (2026-10-30, still present in the served `telegram-login.js`): a failed `/inapp` fetch leaves `inAppRequestPending` set forever — later `auth()` calls silently no-op and `close()` does not reset it. `TelegramWebviewProxy.postEvent` is wrapped the same way as `receiveEvent`; the url-bearing `oauth_request` send is the only observable checkpoint, and when it never fires after `auth()` the lib path is declared dead and clicks route to the manual popup for the rest of the page's life.
