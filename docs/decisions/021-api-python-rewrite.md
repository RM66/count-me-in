# ADR-021: Python (FastAPI) API rewrite

- **Status:** Accepted
- **Date:** 2026-09-26
- **Supersedes:** [ADR-013](013-api-go-rewrite.md)
- **Amends:** [ADR-016](016-standard-openapi-codegen.md) (codegen toolchain: datamodel-code-generator replaces oapi-codegen), [ADR-017](017-runtime-strategy.md) (runtime: Python 3.12 ASGI replaces the Go runtime)

## Context

The API lived in `apps/web/api` + `apps/web/pkg` as a Go module (`countmein`) deployed as a single Vercel Function (`api/entry/index.go`, the "fat lambda" dispatching via `pkg/api.NewMux`) until this rewrite replaced it. The wire contract is owned by the Zod manifests in `packages/contracts` and rendered to `apps/web/openapi.yaml` (ADR-016); the Go side consumed that spec via oapi-codegen and kin-openapi.

The migration replaces the Go implementation with a Python/FastAPI implementation with **byte-compatible HTTP behavior**. Next.js (`apps/web/src`), Auth.js, `packages/*` (Drizzle stays the schema owner), and the Zod contract manifests are not migrated. The full runbook is `docs/migration/python-migration-plan.md`; behavioral goldens were frozen from the Go implementation in Phase 1 (`apps/web/tests_py/parity/golden`).

## Decision

Replace the Go API with a Python 3.12 FastAPI application, deployed as the same single "fat" Vercel Function (one cold start shared by all routes), living at:

```
apps/web/
  api/
    index.py                 # Vercel entry: `from _lib.countmein.app import app`
    _lib/countmein/          # underscore ⇒ not treated as a function by Vercel
```

During the migration the entry lived at `api/_lib/index.py`, not `api/index.py`: Vercel auto-discovers `api/*.py` as functions, and the half-ported Python app must not have deployed next to the live Go one. `api/index.py` was created together with the `vercel.json` switch when the Go function was removed.

Fixed technology choices:

| ------------------------ | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| DB access                | SQLAlchemy 2.0 Core (async) + psycopg 3, `NullPool`, `prepare_threshold=None`                       | Core expresses the conditional `UPDATE … WHERE booked_count + :seats <= capacity` exactly; `NullPool` + no server-side prepared statements is safe behind a transaction-mode pooler and does not leak connections across frozen serverless instances. asyncpg rejected (statement-cache workarounds behind PgBouncer); Prisma Client Python rejected (engine binary bloat, duplicates Drizzle as schema owner) |

Codegen pipeline (amends ADR-016): `bun run generate:py` = `generate:i18n:py` (ICU messages → `i18n/translations_gen.py`) + `generate:openapi` (Zod → `openapi.yaml`, unchanged) + `generate:constants` (now also emits `contracts/constants_gen.py`) + `scripts/generate-py-models.sh` (datamodel-codegen → `contracts/models_gen.py`). The `*_gen.py` files are never hand-edited, same rule as `*_gen.go`. The public OpenAPI document remains the Zod-rendered one; FastAPI runs with `openapi_url=None` so it never serves its own spec.

## Consequences

- **Cold start budget:** Python cold starts are slower than Go's. Mitigations: one shared function (mirrors the Go fat lambda), lazy singletons for engine/Redis/boto3, `includeFiles` limited to `api/_lib/**`, and a review test (`tests_py/test_cold_imports.py`) asserting that importing the app does not pull in `boto3`/`qstash` or open network connections. Phase 6 smoke measures cold start and fails above 3 s; the measured record lives in `docs/migration/perf.md` (local uvicorn baseline: ~0.16 s first request, ~5 ms warm p50 — serverless figures to be re-captured on the next preview deploy).
- **Retired Go byte-emulation (post-cutover wire change):** the Go-compatible encoder (`gojson.py`, HTML-escaping `< > &`, sorted map keys), Go `ServeMux` 404/405 plain-text bodies, and the emulated google/uuid parse-error text on `/api/slots/{id}` are gone. The wire format is now: stdlib `json.dumps(ensure_ascii=False, separators=(",", ":"))` with model field order; unknown routes and methods answer the localized JSON error envelope (`ApiErrors.notFound` / `ApiErrors.methodNotAllowed`, added to every locale); a malformed UUID path parameter answers the JSON `invalidInput` envelope on every `{id}` route (dependency `uuid_path_param` in `web/deps.py` — one rule, no per-path special case). The parity goldens were re-recorded from the Python app with the permanent regenerator `tests_py/parity/record.py` (the retired Go recorder is gone; the replay test and the recorder share one harness, so goldens can only drift with behavior). The golden diff of this change is exactly: response-header order, JSON key order (field order instead of Go's sorted keys), and the new JSON error envelopes.
- **Bundle size:** the function must stay under 200 MB unzipped (Vercel limit 250 MB), checked after `vercel build`. `maxDuration` stays 10 s; `memory` is omitted — the Go config's `memory: 1024` is dropped (the key is ignored under fluid compute; omitting it also avoids any Hobby-tier deploy rejection over configurable memory).
- **i18n stays hand-rolled (evaluated and rejected):** Babel was evaluated and rejected — it is a multi-MB dependency whose locale data loads at import time, directly threatening the cold-start budget (< 3 s) and the bundle cap above. The hand-rolled ICU subset (`i18n/format.py`, `i18n/plural.py`) is shared-vector-tested against the TS side, and the per-locale month/weekday tables in `jobs/templates.py` are 8 locales × ~20 short strings pinned by the notification golden tests — smaller than the machinery that would generate them from CLDR. Revisit only if a locale beyond the app's eight is added or the copy needs full CLDR calendar rules.
- **Deploy dependency source:** `requirements.txt` (the uv export) is the file Vercel installs; `pyproject.toml` + `uv.lock` are the source of truth and CI re-exports and fails on drift, so the two can never disagree at deploy time.
- **Two implementations during migration:** Go stayed buildable and deployed until the Phase 5 parity gate re-verified the goldens and the Go source was deleted; the Python suite is now the only API implementation. `vercel.json` targets `api/index.py` (the switch happened at the Phase 6 cutover).
- **Behavioral compatibility was the goal, not improvement:** every Go quirk was ported as-is and recorded; deliberate fixes happen only after cutover. Byte-level JSON rules (HTML escaping, key order, no trailing newline) are pinned by the Phase 1 golden transcripts and replayed in CI. The permanent record of the deliberate deviations is the "Known deliberate deviations" section below.
- **Known deliberate deviations** (permanent behavior, kept on purpose; each lists how to change it):
  1. **Rate limits enforced in code but absent from the route manifest.** `routes.ts` documents `rateLimit` only for telegramGuest, telegramSignup, createBooking, and the two upload-target endpoints. The handlers additionally enforce: `POST /api/organizers` — `rl:register:<ip>` 10/hour; `POST /api/bookings/lookup` — `rl:lookup:<ip>` 10/min; `POST /api/bookings/cancel` — `rl:cancel:<ip>` 10/min. Kept: the spec documents a subset, which is its stated intent ("Documented for the spec and for the 429 response; enforcement is in the handler"). To change: decide whether the extra limits belong in `routes.ts` (roadmap item), then add them to the manifest — behavior and spec must move together.
  2. **FlexTime rejects date-only strings; Zod's `coerce.date()` accepts them.** The `date-only startsAt` vector cases (CreateTimeSlotInput, UpdateTimeSlotInput) are `valid: false` with a `skip.ts` — the API stacks are the contract, and local-midnight parsing is exactly what the API must not do. To change: fix Zod's acceptance in `packages/contracts` and drop the `skip.ts` on both sides of the vector.
  3. **Log line `time` format is UTC milliseconds** (`2026-09-26T22:15:04.123Z`), not Go's RFC3339 with nanosecond precision and a local offset. Kept: the field is a timestamp either way, drains parse both, and no consumer pins the format. To change: unify in `countmein/logx.py` if a drain ever needs it.
  4. **Access log for `/api/healthz` is excluded.** The Python middleware writes a per-request access log (a Python-side addition) and excludes healthz, matching the one production Go behavior on this point (healthz never reached a request logger). To change: drop the exclusion in `web/middleware.py`.
  5. **Healthz panic scope is narrow.** The probe reproduces the panic path only for the empty-`POSTGRES_URL` case (the common misconfiguration); other init errors (e.g. an unparseable `REDIS_URL`) surface as an ordinary per-dependency `"fail"` in the 200/503 body — still a 503, only without the panic-shaped body. To change: widen the panic path in `routes/healthz.py` if a drain ever needs the distinction.
  6. **Wrong-purpose/expired ticket on organizer registration answers `ticketExpired`, not `authSessionExpired`.** The Go port answered the guest flow's wrong-purpose ticket with `TicketExpired` but registration with `AuthSessionExpired` — two wire keys for one rule ("answered like an expired one, so the endpoint cannot be used to test whether a ticket exists"). Unified on `TicketExpired` (the `organizers-register` golden was re-recorded from the Python app); the `AuthSessionExpired` class was removed (a missing organizer session answers `DemoReadOnly` per ADR-010). To change: re-introduce a distinct error class and re-record the golden.
- **Event-loop affinity of the process-wide clients is handled in the accessors.** The Redis client and the shared `httpx.AsyncClient` are cached per process _keyed by the running event loop_: `redis.client()` / `asyncclient.client()` compare `asyncio.get_running_loop()` with the loop the cached client was built on and rebuild the client when a serverless reuse serves a later invocation on a fresh loop (the old-loop client is left to process teardown — `aclose()` on it is unsafe from the new loop). Pinned by `tests_py/web/test_loop_affinity.py`. The Postgres engine needs no such guard: NullPool opens a fresh connection per checkout, so nothing is bound to a loop.
- **Module-level singletons stay, with a DI seam on top (amended post-migration).** The single-function deployment means one process serves every route, so the process-wide lazy accessors (`redis.py`, `db/client.py`, `web/asyncclient.py`) remain the production path — they keep cold-start lazy initialization and the lifespan owns disposal. On top of them, `web/deps.py` now exposes `get_db_engine` / `get_redis` as FastAPI dependencies: they resolve `app.state.db_engine` / `app.state.redis_client` when set (the per-app override a test or an embedding uses, one level below `app.dependency_overrides`) and fall back to the singletons. The three merge-patch PUT handlers take the engine via `Depends(get_db_engine)`; the rest of the call sites keep the direct accessors until a need arrives. To change: migrate remaining call sites to the dependencies and drop the accessors.
- **One SQL strategy: typed SQLAlchemy 2.0 (migrated from raw `text()`).** The query layer was migrated off hand-written SQL: the `BOOKING_COLUMNS`/`SLOT_COLUMNS`/`SERVICE_COLUMNS`/`ORGANIZER_COLUMNS` projection constants, the `SLOT/BOOKING_CHAIN_SELECT` strings and the positional `scan_*` mappers in `db/rows.py` were removed with the repository migration (ADR-022) — every live read maps ORM attributes via `from_model_*`, where a reordered column cannot silently swap fields. Drift is pinned two ways: `test_models_match_schema` (`alembic check` against a scratch DB) and `test_tables_match_schema` (model tables vs live `information_schema.columns`, plus the enum value sets). The atomic seat reserve stays a single conditional `UPDATE … WHERE booked_count + :seats <= capacity … RETURNING` inside the booking transaction, pinned by `test_seat_reserve_is_single_conditional_update`. To change: never reintroduce positional row indexing — extend the repositories instead.
- **Generated models use type aliases, not `RootModel` wrappers (post-migration).** `scripts/generate-py-models.sh` passes `--use-type-alias`, so scalar schemas render as `type Contact = Annotated[str, Field(max_length=300, min_length=1)]` instead of `class Contact(RootModel[str])`. The former `unwrap_root()` helper (and its ~60 call sites) is gone: fields arrive as plain values, psycopg adapts them directly, and the hand-written `contracts/models.py` was deleted. Constraints are unchanged — the alias carries the same `Field` metadata, and the validation vectors pin both sides.
- **pytest runs in parallel (`pytest-xdist`).** `bun run test:py` runs `uv run pytest -n auto`; the session fixture in `tests_py/conftest.py` gives each xdist worker a private slice — a per-worker Postgres database (dropped, created, migrated from the same Drizzle files, demo-seeded) and a per-worker Redis logical DB — because the parity replay TRUNCATEs every table and FLUSHDBs. Without `-n` the fixture is a no-op and the suite behaves exactly as before.
- **Demo seed has one implementation (post-migration dedup, amends ADR-010):** the Python seed (`api/_lib/countmein/db/seed.py`, what the daily QStash `demo-refresh` job runs) is the only copy; the former TS duplicate (`packages/db/src/seed/`) was deleted. `bun run db:seed:demo` delegates to the Python seed via `uv run python -m _lib.countmein.db.seed`. To change: move the seed only with the refresh job that owns it.
- **Invariants carry over unchanged:** atomic seat reserve, demo organizer write refusal, consumed guest ticket, QStash publish after commit, outbox idempotency, manage-token hashing/expiry, delete 409 guards, media cleanup, healthz, rate limiting, `TRUST_PROXY_HEADERS`, `STRICT_ENV`, i18n of API errors — each gets an explicitly named test (`tests_py/test_invariants.py`, Phase 4).
- **CQRS boundary is preserved:** Next.js keeps server-side Postgres reads for pages; all writes go through the Python API over HTTP, authenticated by the same `X-Organizer-Auth` HS256 token minted in `proxy.ts`.
